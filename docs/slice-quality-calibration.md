# 切片质量人工校准

## 目的

这份校准材料用于把“值得投稿的切片”从抽象描述变成可验证的共同标准。
模型的 `keep/drop` 只能作为待校准答案，不能直接当作人工真值。

当前阶段的目标不是预测播放量，而是判断一条片段是否已经达到“陌生观众能看懂、看得下去、看完有落点、值得投稿”的最低质量。

## 标注方式

观看样本时尽量打开声音，并先完整看一遍，再填写一行 JSONL：

- `human_decision`: `keep`、`review` 或 `drop`
- `human_reason_codes`: 一个或多个原因代码
- `human_notes`: 用一句话说明关键判断
- `manual_trim`: 如果你认为边界需要调整，填写相对样本开头的 `start` / `end`

三种决策的含义：

- `keep`：愿意作为投稿候选，最多只需要常规字幕或边界微调。
- `review`：有看点，但需要人工补上下文、重剪边界，或你暂时无法确定。
- `drop`：即使重新调整边界，也不值得作为独立切片投稿。

原因代码：

| 代码 | 含义 |
| --- | --- |
| `standalone` | 不依赖原直播上下文也能理解 |
| `hook` | 开头很快建立问题、冲突或期待 |
| `arc` | 有铺垫、发展和自然落点 |
| `payoff` | 有明确笑点、反转、答案、情绪释放或信息回报 |
| `story` | 有完整故事、经历或观点展开 |
| `emotion` | 情绪反应强且有来源 |
| `interaction` | 弹幕、SC 或观众互动构成主线 |
| `weak_hook` | 开头太慢或进入状态太晚 |
| `missing_context` | 缺少前因，陌生观众看不懂 |
| `no_payoff` | 有铺垫但没有真正的爆点或落点 |
| `abrupt_start` | 从半句话、半个反应或结论中间开始 |
| `abrupt_end` | 在半句话或未完成的互动中结束 |
| `only_reaction` | 只有笑、惊讶或情绪，没有可理解的事件 |
| `danmaku_noise` | 弹幕很多，但视频内容本身没有价值 |
| `duplicate` | 和另一条候选表达同一个看点 |
| `technical` | 音画、字幕或文件质量影响观看 |

不要为了凑数量给出 `keep`。如果你觉得“有点意思但还不能发”，使用 `review`。

## 样本准备状态

旧评测视频已经做过一轮独立的媒体核验，并有了第一组三条人工标签。核验结果记录在：

`docs/slice-quality-sample-verification.md`

其中明确区分了模型输出、ASR/画面观察和用户人工判断。旧评测的标题、摘要和 `keep/drop` 不能直接当作人工标准。

正式样本仍必须同时记录：

- 可播放的候选视频；
- 独立核验的内容摘要或逐段转录；
- 模型原始判断；
- 人工 `keep/review/drop` 和原因。

在样本数量扩大并覆盖更多内容类型之前，不仅凭这三条修改模型提示词和质量阈值；后续迭代应优先针对“爆点识别错误、边界过长、普通下播误报”收集更多样本。

## 每轮迭代的验收

每次调整只针对一个主要失败类型，并在固定样本集上比较：

1. 模型与人工决策是否一致。
2. `false_keep` 是否减少。这是最高优先级，因为它会产生低质量投稿。
3. `false_drop` 是否没有明显增加。
4. keep 样本的开头、爆点和结尾是否覆盖正确。
5. 人工 `review` 是否越来越集中在真正需要人工判断的边界案例。

没有人工标签之前，不改变模型提示词和质量阈值；先把“好切片”的共同标准固定下来，再让自动迭代围绕分歧最大的失败类型推进。
